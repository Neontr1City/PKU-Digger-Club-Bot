# 问卷星与自建投票的取舍

最新决定（D008）：用户明确无旧队列、不在意刷票，按简单完全自建路线推进提名与投票；不再集成问卷星。下文保留为选型时的比较记录，“尚未选择”等措辞仅描述当时状态。现行实现范围见 [开发计划](development-plan.md)。

更新：2026-09-27。用户要求比较路线，尚未决定替换问卷星；D004 继续有效。本轮仅研究和设计，没有创建网站、迁移答卷或部署服务。

## 针对本群的判断

约 200 人、每天一至数组固定双曲投票，适合开发一个小型活动网站，不需要复制完整问卷平台。自建最有价值的是程序直接管理数据和音乐页面；主要代价是自己负责投票身份、页面可访问性、数据备份与故障修复。是否换路线，取决于对“每微信账号一次”的要求和问卷星实际免费 API 权限。

建议：若接受熟人社群的轻量防重复、希望日常尽量全自动，自建值得优先考虑；若需要方便的微信身份限制且现有免费 API 足够，保留问卷星更省维护。此为建议，不是新增已确认决定。

## 功能比较

| 维度 | 问卷星 | 自建小型活动网站 |
| --- | --- | --- |
| 初次投入 | 现有表单和群友习惯可沿用；仍须开发音乐核对、排期和消息 | 多开发投票前后端与管理入口；若替换提名，再加一个固定表单 |
| 每日自动化 | 取决于读取、创建、发布、截止、统计各项 API 权限；人工导出导入会留下日常操作 | 活动数据在自有数据库，直接排期、截止和计票，不受问卷星接口权益约束 |
| 曲目展示 | 支持图片和外链，但受编辑器布局限制 | 两张歌曲卡片、专辑封面、双平台按钮、多组排版和历史回顾均可定制 |
| 投票身份 | 官方投票文档写默认每微信一次；用户账户的具体行为待核对 | 无登录版只能识别浏览器；微信身份、邀请码或账户体系需另选 |
| 结果 | 需要取回统计，再由活动程序生成定制 PNG | 直接用数据库冻结的统计生成 PNG；并非自建才可以做结果图 |
| 群友使用 | 沿用原有链接和流程 | 仍可“群链接→手机网页→投票”；要验证微信打开及听歌后返回的体验 |
| 费用 | 普通表单与高级接口是不同权益，用户 API 免费情况未验证 | 无问卷 SaaS 订阅费，但云资源、可选域名及后续维护仍有成本；Azure 赠金不是永久免费 |
| 维护与数据 | 平台负责问卷服务运转，管理员保留必要导出 | 我们维护程序、管理员访问、数据库和备份；故障期间投票可能不可用 |
| 微信自动发群 | 仍需单独解决账号接入 | 同样需要，换投票工具不能解决微信群发送接口问题 |

依据：[问卷星编辑器图片／外链](https://www.wjx.cn/help/help.aspx?helpid=435)、[投票入门及微信次数限制](https://www.wjx.cn/help/help.aspx?catid=65)。本轮再次核对 [API 总览](https://www.wjx.cn/help/help.aspx?h=1&helpid=333) 与 [ApiKey 说明](https://www.wjx.cn/help/help.aspx?catid=140)：前者标旗舰版，后者说明首次生成默认开放部分接口且权限沿用账户，因此仍不能断言用户必需付费或全部免费。

## 身份识别是主要路线选择

可选择以下强度，不默认替用户决定：

1. **不登录，按浏览器限制。**服务器签发随机标识，每个标识对每组最多一张票，数据库约束阻止重复提交。操作最少，但清除 Cookie、换浏览器／设备仍可能再投；不能称为一人一票。适合以社群信任为基础的娱乐活动。
2. **每位群友独立邀请码或账户。**服务器按身份对每组限制一次，可跨设备保持投票记录，但要分发／恢复身份，邀请码可能转交他人；仍不自动知道谁是群成员。
3. **微信身份接入。**普通网页在微信里打开并不自动获得微信账号 ID；需要另行核对合资格的微信身份产品和授权流程，不能承诺免费、无需注册平台或严格仅群成员可投。首版不默认引入。

一微信账号一次也不等于一自然人一次，更不等于仅本群成员。投票链接被转发后，是否允许群外参与需要单独定规则。昵称不能当身份认证；校园网络共享 IP，也不采用同 IP 只能投一次。

不论选哪种，服务端都须校验截止时间和所属活动，结果以已入库票据为准；不能只在网页上禁用按钮。是否允许改票、跳过及提前看票数仍由管理员决定。保留结果快照和管理员修改记录即可，无需企业级审计系统或压力测试。

## 替换范围有三种

| 路线 | 日常流程 | 尚未解决的部分 |
| --- | --- | --- |
| A. 提名、投票都留问卷星 | 官方 API 或人工操作＋自有音乐／结果程序 | API 权限与每日手工量 |
| B. 问卷星提名＋自建投票 | 定期导入提名，再自动排期、投票、计票 | 提名仍需 API 或导出；不能称为端到端全自动 |
| C. 提名、投票都自建 | 新表单直接入待审核队列，审核后自动排期 | 群友换一个提名入口，旧队列需一次导入；不自动迁移历史所有答卷 |

若决定自建且愿意换提名入口，C 更符合减少日常操作的目标；B 适合平缓过渡。旧问卷可以只保留查阅，不需立即删除。提名提交后仍先做曲目核对；不能将随机提交的名字／链接直接自动发布。

## 足够小的首版范围

- 今日投票：每组两张歌曲卡，各有明确投票按钮和网易云／Apple Music 链接，封面按确认的发行版本展示。
- 提名页（仅 C）：昵称、两首曲目信息、可选分享链接与版本说明，自动记录提交时间及序号。
- 管理入口：审核曲目、按日期覆盖组数、暂停、查看票数和生成群消息／结果图。
- 云端后端与数据库：提交、按规则防重复、按服务器时间截止、结果快照、简单备份和 CSV 导出。

不做内置整曲播放、通用问卷编辑器、排行榜、推荐系统、公开社交账号体系等附加功能。音乐跳转不等于有播放权限，平台地区可听性与正式版本核对仍需单独完成。

## 部署与成本边界

优先评估用户已有 Azure 额度中的小型服务；如果最终微信服务也在同一台云主机且有余量，可以共用主机，增量资源可能很小，但要按实际配置估算。页面与投票后端需要公网 HTTPS；微信服务的管理 API 保持受限，不随投票页一起公开。

另一条候选是 Cloudflare Workers＋D1：官方有免费请求、计算和数据库额度，低流量投票的预估用量有机会覆盖；这是用量估算，不是大陆微信访问效果保证。[Workers 价格](https://developers.cloudflare.com/workers/platform/pricing/)、[D1 价格](https://developers.cloudflare.com/d1/platform/pricing/)

无论哪种平台，先用少量 iPhone／Android 微信里实际打开页面、投票、跳转听歌并返回，再确认部署。若有可用平台 HTTPS 域名，不必首日买域名；域名选项与费用在选定托管平台后核对。图像渲染与微信服务不默认放进免费函数的受限运行环境。

Azure 学生赠金的额度与到期时间以账户为准；不能由“已有赠金”推出整个系统能免费运行一年。费用应包含计算、磁盘、IP／网络和备份，且要留出微信服务所占部分。还没有创建或估价具体实例。

## 如用户选择自建，计划如何变化

P1b 改为投票页微信可达性与投票身份方式验证，先确定轻量防重复还是独立身份；P2 根据 B／C 选择导入器或新提名页；P3 实现小型投票网站；P4 继续复用既有结果规则；P1a 微信自动发送不变。可先独立验证投票流程，不必等待微信协议服务选定。

只做必要功能检查：重复请求不加票、过截止不收票、多组分别统计、管理员入口不能匿名访问、结果与原始票据一致。未选择路线前不实施或迁移。
