# 微信自动推送与掉线提醒

更新：2026-10-07。正式目标为「今天你滚了吗（pku版）」，自 2026-10-08 北京时间 12:00 起运行；此前仅在测试群验收，正式群禁止试发。

## 运行方式

继续使用原 Azure VM 的腾讯官方 Linux 微信 4.1.13.23。界面操作由本项目 `deploy/wechat/sender.py` 完成；不是微信官方机器人 API，也不修改客户端或使用第三方协议。用户手机的微信分身需保留机器人登录。网站、发送程序和邮件任务都运行在云端，本地电脑可以关机。

1. 网站 worker 每分钟执行截止和排期，产生日期固定的消息包。
2. 单独的发送线程每五秒检查进度，按结果图、祝贺、当日曲目／链接的顺序投递。
3. 空闲心跳仍约每 30 秒截图，窗口、位置及群名区域像素完全一致时复用最多五分钟的已核验群名，减少 OCR 子进程反复加载；窗口或像素变化、缓存到期立即重新识别，检查异常即清除缓存。每条消息发送前始终执行完整核验。微信容器读取私有文件队列，每条发送前核验当前群名。只去掉识别出的空白和成员数后缀，不做近似群名匹配。窗口不符、登录失效或留有草稿时暂停，不猜测目标。
4. 文字使用服务器 UTF-8 剪贴板，粘贴后复制回读逐字比较；图片只允许由本站冻结结果生成的 PNG，粘贴后等待异步渲染完成，再对照整张缩略图核验。
5. 点击发送前先写入“不确定”记录。输入区清空且本账号消息气泡／图片指纹确认后，才标记完成并发送下一条。该状态表示客户端画面确认，不是微信提供的服务端送达回执。

官方客户端版本或布局改变后需重新验证，不宣称永久在线。当前适配浅色英文界面的默认布局；不要在任务发送时同时操作云端桌面。为避免误发，不自动搜索同名群；普通使用中不自动切换当前聊天。仅在已请求手机确认的登录恢复阶段，检查可见聊天列表的唯一候选；若列表将名称截短，要求至少八个规范化前缀字符一致并明确出现省略号。打开候选只用于查看，随后必须按完整顶部群名精确核验才允许推送。重复候选、短前缀或核验失败均暂停，同一次手机确认最多打开候选一次。其他人工操作后，请回到指定群并清空草稿。

## 配置

网站私有 `.env.local`：

```dotenv
WECHAT_DESKTOP_ENABLED=1
WECHAT_SEND_ENABLED=1
WECHAT_GROUP=PKU Digger Bot测试
WECHAT_OUTBOX=/app/data/wechat/bot-outbox
```

客户端的 `data/wechat/bot-outbox/config.json`：

```json
{"group":"PKU Digger Bot测试"}
```

两边群名必须一致。客户端读取一次配置，修改目标后需重启发送进程；切换正式运营群须另获用户明确授权并实际核验。不要公开配置文件或整个 outbox。默认 `.env.example` 关闭自动发送。

共享目录在既有登录数据挂载内，客户端只访问自身目录；不向微信容器挂载业务 SQLite、QQ 授权码、网站密钥或 Docker socket。队列／收据均使用原子文件替换、私有权限和 UID 10001，单显示会话只允许一个发送进程。没有新增公网接口或端口。

`wechat_deliveries` 保存每条状态；`wechat_incidents` 保存故障去重与邮件重试。文件夹中的 `requests/`、`receipts/`、`health.json` 都是运行数据，不入 Git。不要直接删除收据来“重试”。

## 掉线处理

旧版邮件主题“微信掉线或推送暂停”涵盖多种异常；现已按检测状态区分。`client_unavailable` 表示窗口、截图或识别检查未完成，不等于已确认账号退出；`check_timeout` 表示界面检查超时；`logged_out` 表示普通登录界面，`phone_confirmation_pending` 表示等待手机确认，`qr_login_required` 表示需要扫码。邮件标题分别提示“微信推送检查异常”与“微信登录已失效”。先看后台当前状态：若已恢复“在线，等待每日推送”，无需仅凭旧邮件再次登录。

- 客户端每约 30 秒更新心跳；180 秒无更新认为发送程序不可用。
- 登录界面、客户端退出、目标群未确认和发送结果不确定均暂停推送。
- 异常持续两分钟后通过既有 QQ SMTP 邮箱发送一次提醒；心跳失联总检测时间通常约五分钟。
- 邮件失败按 15／30／60 分钟退避重试，不输出 SMTP 凭据或原始异常。
- 同一次故障只发一次；连续正常两分钟才关闭故障记录。短暂恢复后再失败仍视作同一次故障；即使已稳定恢复，同类提醒也最多每 30 分钟一次。不额外发送恢复邮件。
- 整台 VM 停机或完全断网时，同机程序也不能实时发邮件；恢复后可继续检测。本实现没有另外购买外部监控。

常见的保留账号登录窗口：发送程序只在较小的启动窗口里识别唯一、明确标注“登录／Log In”的绿色按钮，最多每十分钟尝试一次。点击后，必须实际识别到等待手机确认的界面，才立即发送“请在手机微信确认机器人登录”邮件；这封行动提醒不等普通故障的两分钟观察期，同一次确认请求只发一次，短暂识别失败或发送程序重载不重复提醒；已请求的手机确认即使过期，也不会自动反复续发请求和邮件，需按邮件入口手动处理。用户打开华为手机的微信分身（机器人账号），点击“登录／确认登录”即可；登录后程序尝试返回指定群，并再次核验完整群名。若提示过期或没有手机提示，再打开后台查看；需要二维码时邮件明确要求扫码，不声称只需手机确认。程序不切换账号、不输入微信密码，也不自动确认手机端授权。

登录失效且不能自动请求确认：打开网站管理页 →「打开云端微信」→ 手机分身扫码／确认 → 回到指定群。已确认发送的步骤不重发；排队中的任务恢复后仅续发当天内容。如果某一步已记为 blocked／uncertain，先在后台核对处理，再继续。跨日旧“今天”消息不自动补发。

若管理页显示“不确定／已暂停”，先在群里核对；异常满五分钟后可选「群里已收到，继续下一条」或「确认没发出，重试这条」。这是恢复既有发送步骤，不会创建或提前发布新对决。跨日消息不能用重试按钮重发；可选择「放弃过期消息，不再补发」，无需把未收到的消息误标为已收到。

## 更新发送程序

2026-09-29 起发送程序支持 `SIGHUP`：只设置重载标志，完成正在处理的消息及收据写入后，在下一次空闲循环用同一 PID 重新加载 Python 程序，避免触发桌面监督进程退出。发布时先校验新文件语法、原子替换，再只向发送程序发信号；不要对微信进程发送该信号。早于此版本的发送程序不支持热重载，不能直接发 HUP。

微信 Compose 固定项目名 `pku-wechat`，避免维护时生成第二套容器；登录目录始终只由一个运行的客户端使用。现已切换到常规镜像，诊断 GDB 环境不再运行。

## 正式运行配置（2026-10-07）

网站 `.env.local` 的 `WECHAT_GROUP` 与发送端私有 `config.json` 的 `group` 均为「今天你滚了吗（pku版）」。数据库 `settings.launch_day` 为 `2026-10-08`，发送端 `send_not_before` 为同日北京时间 12:00 对应的 Unix 时间。此限制不会停掉登录检查和邮件；提名照常收集补全，开始前不排期消费，首日排除旧测试结果。

正式群标题可使用私有 `title_reference` 校验已目视确认的完整群名像素区域；范围不含群人数，进退群不影响该校验。不自动校准参考，不使用近似汉字替换。用户已确认不会加入相似名称群，需保持正式群位于置顶首位；`restore_pinned=true` 只在登录恢复时允许打开这一候选，之后仍需标题核验，普通使用不自动换聊天。
