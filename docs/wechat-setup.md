## 用户先准备

2026-09-28 用户已确认独立账号注册完成，并指定测试群「PKU Digger Bot测试」（Bot 与“测试”之间没有空格）。后续联调只以此群为目标；已登录并视觉核对群标题，发送程序固定核验此群标题；界面路线没有取得协议层唯一群 ID，不自动搜索同名群。2026-09-30 起，手机确认后可受限恢复当前指定群，仍须完整标题核验；边界见 [发送与恢复说明](wechat-delivery.md)。

1. 一个由用户本人掌握、可正常使用的独立普通微信账号，用来作为机器人群成员；有现成备用账号即可，不预设需要购买手机号、设备或账号。不是公众号或企业微信机器人。第三方自动化不是腾讯正式群接口，存在登录限制或账号受限可能，因此不建议直接用日常主号测试。
2. 能操作该账号的手机，便于本人扫码、确认登录及处理偶发验证；不提供密码、短信验证码或远程接管手机。是否要求手机持续在线需按最终实现验证，不能提前保证永久登录。
3. 已指定测试群「PKU Digger Bot测试」，机器人账号也加入；不用真实 200 人运营群试发。
4. 接下来在自己服务器的管理员入口打开云端微信，用新注册的机器人账号扫码确认。目标群核验后再做小样验证：结果 PNG、祝贺文字、曲目和投票链接，并用手机查看显示与链接；确认重试不重复发、登录失效能暂停。不是规模化或长期稳定性测试。

暂时不需要购买服务 token、iPad、Windows 服务器或升级现有 VM，也不需要把账号密码／登录状态提交 Git。现有 Azure 网站与已登录微信客户端共用同一主机，文字／PNG 小样已试发；登录后的资源快照见 wechat-cloud-probe.md，尚不能承诺长期免扫码。

## 当前边界与待选择路线

- 用户方向继续是独立账号、普通微信群、云端常驻、不依赖本地电脑、免费优先。管理员转发只作为讨论后的后备，不替代最终自动发送目标。
- OpenClaw 微信文档仍明确：腾讯微信团队维护的插件声明支持私聊与媒体，能力元数据没有声明群聊。因此不能据此让用户准备 ClawBot 即承诺发到原群。[OpenClaw 微信文档](https://docs.openclaw.ai/channels/wechat)
- 云端第三方协议是与现有目标较接近的候选，但要先确认具体发行物、授权、当前扫码登录、文字／PNG／普通群发送能力。WeChatPadPro README 提供 Linux 路线并列至少 2 GB 内存，不能假设当前 1 GiB 网站 VM 直接足够；尚未运行或确认免费可用版本。[项目仓库](https://github.com/WeChatPadPro/WeChatPadPro)
- Wechaty 是框架，其服务 token 文档区分短期试用、贡献者长期免费、付费长期使用；不将“框架开源”或“短期可用”当作长期免费方案已解决。[Token 文档](https://wechaty.js.org/docs/puppet-services/tokens)
- 云 Windows 桌面自动化是另一条比较路线，仍属非官方自动化，另需核对云桌面费用和断开远程连接后的运行条件。尚未选择、创建或付费。

上述协议／服务路线保留为比较记录。按 D025，当前先验证原生 Linux 微信＋界面自动化；扫码由用户本人操作，不索取微信密码。找到 GitHub 项目不等于已验证账号能登录。

新增比较候选：官方 Linux 微信客户端在云端虚拟显示中运行，再补最小界面自动化。WechatOnCloud 提供这种架构的公开实例，但不是现成的自动群发接口；资源、登录与图片发送仍需验证，详见 related-projects.md 第 7 节。

2026-09-28 已在原服务器启动官方 4.1.13.23，解决 EGL／Pulse 客户端动态库缺失，无需额外云资源。不同内存统计口径、后备方案费用及当前实测边界见 [云端客户端验证方案](wechat-cloud-probe.md)。

## 项目侧要完成的连接

`service.prepare_dispatch` 生成有序内容，网站发送线程与客户端程序通过私有 outbox 交接，逐条记录 queued／confirmed／blocked／uncertain。`wechat_sent` 读取实际发送包状态，不再固定为 false。发送不确定不盲重发，后台可在核对后确认或重试；掉线和发送异常通过既有 QQ SMTP 去重提醒。唯一联调群仍为测试群，正式群切换需要另行确定。
