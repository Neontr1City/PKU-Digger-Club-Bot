# 自动提名处理标准

规则版本：`2026-10-08.1`。用户于 2026-09-27 确认：以无需管理员参与为默认；单个平台链接缺失直接接受，不通知管理员。这里区分已实现流程、判断规则和外部能力边界。

## 实际流程

1. **接收**：保存提名时，将原始艺人／曲名、两首一组的关系与顺序保留在 SQLite，同时创建唯一处理任务。昵称和备注不发送给曲库。
2. **规范比较键**：解码 HTML 实体、整理空白、Unicode 归一化。比较时忽略大小写、标点和拉丁字母变音符差异，统一假名宽度及平／片假名，但保留浊音和半浊音区别；展示文字采用来源中的原文，不使用程序 title-case，也不让语言模型凭记忆改名。
3. **检索候选**：查询网易云网页目录、Apple 中国区 iTunes 目录与 MusicBrainz。必要时使用 MusicBrainz 模糊词项查询恢复轻微拼写错误；用找到的名称继续查询 Apple 美区和网易云曲名搜索；涉及汉字／假名或仍不能识别时，增加 Apple 日区候选。候选仍须通过原始艺人和曲名检查，不能因扩大搜索范围而换成翻唱。
4. **识别录音**：检查艺人身份、曲名和版本；比较跨平台时长，避免把现场／混音／重录接到普通录音上。仅接受检索实际返回的歌曲 ID 与链接。网易云候选另读歌曲详情，确认 ID、名称、时长和封面。
5. **选发行**：优先 MusicBrainz 正式发行的 Album／EP 且无 Live／Compilation 等附加类型；其次优先跨平台专辑名一致的发行，再优先 Apple 发行信息及早期日期。标题带有 greatest／best of／collection／compilation 等的合集降低优先级。无法证实最早正式专辑时保留平台发行与说明，不冒称已核定首版，也不因此打扰管理员。
6. **确定封面**：封面与所选发行绑定，实际下载确认图片可用并缓存；国区听歌链接与封面分别选择，同录音有更合适的正式专辑发行时优先其封面并保存独立证据；下载失败尝试另一个已匹配发行的封面。没有可用封面时使用明确标注的缺失占位，仍可入队。
7. **保存并入队**：两首都有可信匹配且至少各有一个听歌链接，即自动设为就绪。保存显示名称、专辑、平台原始名称／时长／ID／地区、采用来源、查询记录、修正对照、时间与规则版本。原始提名不改写。
8. **异常处理**：找不到可信歌曲、同名身份无法区分、近似候选相互冲突、两侧实际同曲，或备注存在不能确定对应录音的版本要求时保留待处理。外部源暂不可用导致无法完成时，15 分钟后重试，最多 3 次；可由管理员重新查找。单个平台或封面缺失属于接受状态，不进入异常队列。

自动补全与自动排期是两回事：补全只把提名准备好，不创建当天投票，不发送微信。队首无法处理时继续遵守原有顺序，不擅自跳过。

## 匹配规则的具体含义

- 艺人、曲名分别采用归一化字符串相似度；单次替换、插入、删除及相邻字符交换可作为常见 typo 处理，短于四个字符不启用这一宽松规则。
- 艺人可匹配完整署名、已验证别名或曲库明确列出的参与艺人；不会仅按 `&`、逗号拆分乐队名称。候选的艺人与曲名分数均须 ≥ 0.84，平均 ≥ 0.91；先按用户署名要求选优先组，再比较分数；离最高分 0.035 以内的候选若指向不同曲名或互不相容的艺人身份，才视为不能确定。合作阵容不同本身不阻塞，见下节更新。**这些分数是启发式规则，不是正确率或概率。**
- 同一平台、相同艺人名称若对应不同艺人 ID，不自动合并；同名艺人 ID 完全无交集时仍拒绝；共享所填艺人身份的合作版本可以选其一，但不把不同合作阵容的链接合并成同一录音。若冲突只出现在某些候选中，仅当另一个候选有唯一的、与 MusicBrainz 正式 Album／EP 发行和录音时长交叉吻合的证据，才先排除未获同等证实的候选；多个身份各自有正式发行证据时仍保留待处理。
- Remastered／Remaster 和对应重制年份可互换、展示时省略；原始返回仍留在证据里。现场、混音、Demo、原声、伴奏、重录、Take、Radio Edit、Mono／Stereo 不按重制版规则抹去。`feat.`／`ft.`／`featuring` 是署名信息，按下节处理；其他未识别的括号内容保留。
- 同一录音的跨平台连接要求归一化艺人、曲名一致（或通过下文的来源别名对应）、版本兼容，并且都有时长；允许差值为 `max(4 秒, 较短时长的 2%)`。这不是同一母带的证明。无法满足时仅保留优先发行的一个可信链接。
- 封面只使用对应发行返回的 CDN 地址；平台原始名称、专辑名和封面来源可在后台查阅。无法从来源证实的字段留空或标注未核实。
- 有特殊版本要求时，最好写在曲名中，例如 `Song (Live at …)`。备注中的版本要求不能静默忽略，无法判断时保留待处理。

## 艺人和曲名填反时的候选（2026-10-08）

正常方向完成现有检索后，如果没有平台条目通过艺人、曲名及版本检查，额外把原始曲名作为艺人、原始艺人作为曲名，查询网易云、Apple 国区与 MusicBrainz；反向结果没有可信 Apple 国区候选时，最多再查一次 Apple 美区。不对已有可信匹配但发生身份／曲名冲突的情况触发反向搜索。

反向结果必须按互换后的输入通过相同匹配门槛，才标为「可能填反」候选。它们优先显示于人工审查列表，并与正常搜索的相同平台链接去重；仍遵守每平台 20／20／10 条报告上限。报告保存互换搜索词、查询方向、来源及结果数量，原始输入保持不变。即使反向匹配分很高，也不自动填入确认结果或入队；管理员选择、核对并确认后才保存。

已有可选择的反向平台候选时，任务进入人工审查；其他曲库暂时失败不延迟这一确认入口。没有可选择候选时仍遵守原有错误重试机制。

## 汉字、假名与罗马音

不使用机器翻译、日文转写库或语言模型猜读音来确认歌曲。输入原文始终保留，最终展示使用所选平台元数据。

1. Apple 日区／美区／国区可能对同一条目提供不同文字。仅在 **歌曲 ID 与艺人 ID 都相同、时长兼容** 时，建立该录音的艺人和曲名别名。例如已实测 `青葉市子 — いきのこり●ぼくら` 与 `Ichiko Aoba — Ikinokori●Bokura` 共用歌曲 ID `720743504`。名称配对及各地区真实来源均存入 `alias_evidence`。
2. 假名读音或姓名次序不在 Apple 元数据中时，可查 MusicBrainz 的艺人名称、别名与排序读音。必须查到唯一艺人记录，且原始输入恰好符合其中的名称／读音才采用；不能只因为搜索结果排第一就确认。来源异常或读音缺失时，维持已有可信单平台结果，或保留未确定项。
3. 这些对应关系只在本次歌曲查找中使用。网易云仍须有匹配名称、版本和时长，其详情也要一致；不按相近读音合并其他艺人，不把翻唱当作同一录音。别名通过多步关联时保留完整证据链。
4. **Apple Music 国区优先**。先搜国区；从其他地区识别出可信歌曲后，额外用最多 3 个实际候选 ID 查询国区。只使用 API 实际返回且指向 `/cn/` 的链接，不把 `/us/` 或 `/jp/` 文本替换成 `/cn/`。无法取得可采用国区条目时才保留其他地区。

`cricket/aliases.py` 管理这种有来源的对应关系；后台提名详情的「候选与来源记录」可查看名称、歌曲 ID 与来源。MusicBrainz 艺人查询缓存一小时；Apple ID 查询遵守现有平台限频。此功能不会回写已排期投票。

## 缺失与地区处理

| 情况 | 默认动作 | 是否需要管理员 |
| --- | --- | --- |
| 两个平台均找到且录音兼容 | 保存双链接并入队 | 否 |
| 只找到网易云或 Apple Music | 保存该链接，另一平台显示暂未找到 | 否 |
| 两个平台候选录音冲突 | 保留可信度更高的发行链接，记录另一链接缺失原因 | 否，前提是歌曲身份确定 |
| 没有可用封面 | 显示封面暂缺，继续入队 | 否 |
| 暂无独立来源证明首版专辑 | 使用平台发行及封面，记录未交叉验证 | 否 |
| Apple 国区有已确认的对应歌曲 | 优先保存国区链接，即使身份识别借助日区／美区 | 否 |
| Apple 国区搜索及 ID 查询均未取得对应条目 | 保留已确认的海外区链接，标明美区／日区 | 否 |
| 歌曲身份无法确定，或两个平台都没有可信歌曲链接 | 保留待处理及候选 | 是；先尝试自动重试可恢复的查询错误 |

公开可访问的元数据和链接不代表用户在所有地区／账号下都能完整播放。地区不凭 URL 字符串替换伪造，缺失歌曲 ID 不凭经验编造。

## 程序与操作入口

| 文件／入口 | 职责 |
| --- | --- |
| `cricket/music.py` | 三个曲库适配器、请求间隔、1 小时查询缓存、歌曲详情 |
| `cricket/matching.py` | 比较键、typo、版本、同录音及发行优先级规则 |
| `cricket/enrichment.py` | 多源查询、证据、选择策略、入队与失败重试 |
| `cricket/artwork.py` | 有来源约束的封面下载／缓存 |
| `enrichment_jobs` 表 | 独立任务状态，不修改原有已排期快照 |
| 管理后台 → 提名详情 | 状态、修正对照、封面、链接、候选及采用原因；必要时重新查找或人工修正 |
| `uv run python -m cricket resolve` | 处理一组待处理提名后退出，适合验证 |
| `uv run python -m cricket worker` | 每分钟尝试领取一组（前一组未结束则等待）；独立执行日常结算与排期 |

仅启动网页不会执行任务。部署时网页和 worker 指向同一数据库、OUTPUT_DIR；保留一个 worker 即可。Docker Compose 的 `schedule` profile 已包含 worker。自动排期关闭时，worker 仍处理提名。

重复提交不会创建重复任务；已就绪、已跳过、已排期内容不被后台改写。任务执行中管理员修改／跳过的结果优先；进程中断超过 15 分钟可重新领取任务。人工重新查询只针对待处理项。旧数据库中原有待确认条目不批量重写，可在详情页点击自动查找。

只有处理报告进入人工审查，或查询错误达到重试上限时，提名详情才显示可选择的平台曲目。自动就绪、正在查询、仍可自动重试的提名不出现该选择。报告按 Apple Music、网易云、MusicBrainz 分别保留最多 20／20／10 条有排名的证据；其中仅带有可验证平台歌曲链接的 Apple Music 与网易云条目可一键填入审核表单，MusicBrainz 继续用于核查证据。选中网易云候选后，仅按该曲目 ID 查询详情，核对平台／曲目 ID、来源、艺人身份、曲名、版本和时长一致后，补齐其发行与封面。只查询选中的条目，不重新搜索或换歌；详情缺失或不一致时保留已知信息并提示。审核表单显示对应封面预览。选择只是预填，不修改队列；管理员须核对录音版本、链接与封面来源，再勾选确认并提交。旧报告可能只保存 12 条候选，待处理项可点击重新查找以取得较完整列表。

## 外部能力与来源（2026-09-27 查证）

- [Apple iTunes Search API 官方文档](https://performance-partners.apple.com/search-api)：无需开发者 Token 的目录搜索，包含曲名、艺人、专辑、时长和图片字段，支持地区参数。按官方约 20 次／分钟说明，本实现间隔至少 3.1 秒并缓存；iTunes 搜索不是完整 Apple Music 目录。中国区空结果不能证明 Apple Music 没有此曲。
- [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) 与 [搜索字段](https://musicbrainz.org/doc/MusicBrainz_API/Search)：录音、艺人身份和发行类型用于交叉核验；本实现请求间隔至少 1.1 秒。社区数据库也可能缺项或出错，不是发行商认证。
- 网易云直接读取其域名下的 [网页搜索](https://music.163.com/api/search/get?s=April&type=1&limit=5) 与 [示例歌曲详情](https://music.163.com/api/song/detail/?ids=%5B4021290%5D)。本机实际返回 JSON，含歌曲 ID、艺人、专辑、时长及封面。**没有找到可保证这一接口长期受支持的官方开发文档**；不使用第三方代理、不登录、不下载音频。限频或接口变化时记录失败并回退。
- [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API) 是发行封面的后续候选渠道，本版尚未接入。艺人／厂牌官网、Bandcamp、Discogs 是罕见未匹配项的补证来源，目前未实现这些网站的自动抓取，不把它们计入自动覆盖率。

### 历史提名样本发现（2026-09-27，规则 .2 基线）

42 组旧提名已在本机分栏，抽取 12 组真实查询，细节见 [验收记录](prelaunch-validation.md)。规则 .2 对有来源的常见缩写与部分 typo 有恢复能力；漏填 feat. 或合作发行中的另一位艺人，会出现已搜到正确候选却无法自动匹配的情况。这是待改进项，不应归咎于歌曲不存在。Side A／Side B 与作品名不同、完整作品和多个分段并存时仍需可靠来源或明确选择。此轮只测试和整理输入，未修改生产规则。


## 客串与合作艺人（规则 .3，2026-09-27）

用户明确 feat.／合作艺人不属于曲名，不应因提名漏填这些信息而阻止自动通过。按此要求：

- 从歌曲字段提取明确的 `(feat. B)`、`[ft. B]`、尾部 `featuring B` 等署名。曲名展示和匹配使用主体；实际客串署名移到艺人展示，并在 `featured_artists`、平台原始字段及来源里保留。不会移除 Live、Remix、Part 2 等版本信息，也不会删除未知括号。
- 网易云 `artists` 数组与 MusicBrainz `artist-credit` 明确列出的成员可用于匹配。平台列 A 与 B 合作时，用户只填写 A 或 B 可通过；不把乐队名中出现 `&` 当作成员证据。
- Apple 只有组合署名时，可借用同完整署名、同曲名、时长兼容的来源成员列表，记录 `artist_credit_source`。此关系只用于本次候选，不建立跨歌曲的“A 就是 A+B”别名。
- 用户未写客串人时不强制补填；若明确指定客串人，仍检查候选署名。规则 .3 曾因不同合作阵容而停下；2026-09-28 按用户要求由下节的署名优先级替代。跨平台链接仍不混合不同合作录音。
- 跨平台仍核对歌曲版本、时长和可用的艺人身份；平台一侧缺少客串文字本身不阻止链接对应。完整平台返回与署名证据保留，未修改既有历史快照。

真实复测使用旧表仅分栏的原始输入，没有手动补 feat. 或 Harold Budd：两组均自动就绪，四首均取得 Apple 国区链接；三首双平台，恐龙的皮一首保留可信 Apple 单平台。纯曲名为 `Millions of Years Apart`，客串 MANDARK 出现在艺人署名；`Sea, Swallow Me` 保留 Cocteau Twins & Harold Budd 的联合署名。报告在忽略目录 `output/credit-validation-20260927/`。76 项测试通过，覆盖漏填署名、显式错误客串人、翻唱、现场、分段、乐队名、合作阵容冲突及来源缓存不被改写。

## 单人优先与多人输入（2026-09-28）
